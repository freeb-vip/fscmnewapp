# PDA 广播扫码返回保护

本次只涉及原生 Android 输入与导航，不修改后端或库存写入。

## 行为

- 有效条码广播启动 600 毫秒保护，使用 Android uptime 单调时钟。状态广播不覆盖有效扫码时间，也不使自动识别的广播模式退回键盘模式。
- 受保护的系统返回不调用页面业务返回逻辑。按键按下、重复及抬起按设备、键码和 downTime 配对；即使抬起超过保护窗口，也不会漏出返回。
- 所有 FSCM Compose 页面返回和弹窗共用保护入口；弹窗同时处理独立窗口按键和无 KeyEvent 的返回回调。
- 页面按钮的触摸返回、取消、弹窗外部点击继续沿用原行为。600 毫秒内人工按系统返回键也可能被拦截，可使用页面返回按钮。
- 广播模式且页面正在接受扫描时，保护窗口内附带的 Enter、数字键盘 Enter、Tab、Esc 会被消费。正在人工编辑时放行这些按键；通过 Compose 输入会话和原生窗口编辑状态判断，不读取输入内容。
- 盘点、收货、入库、装箱点数和离线发货页面显式声明扫描状态。数量输入、相机、确认及不可扫描阶段不启用附带按键过滤；返回保护仍有效。
- 切换模式、离开前台及退出登录会清空返回保护和未完成的按键配对。
- 广播前或保护窗口外的返回不延迟、不猜测性拦截。摄像头识别不会启动广播保护。

## Android 9 PDA 复现

1. 进入“PDA 设置”，开启“记录扫码事件”。
2. 返回发生问题的业务页，以相同条码和操作方式复现。无需提交真实库存。
3. 回到“PDA 设置”，使用“复制诊断”。可在“清空结果”后开始另一轮复现。
4. 结束后关闭记录。最多保留本次进程内最近 100 条事件，重启不会恢复。

复制内容包括 App/Android/设备版本、有效广播、控制键来源、相对扫码间隔、是否拦截及原因、导航请求和路由变化，不包括条码或字符键内容。页面原有“最近条码”显示不变，但复制诊断不再包含条码。

诊断原因：`scan_guard` 表示已拦截；`outside_window` 表示广播前或超时；`manual_editor` 表示人工编辑；`scan_inactive` 表示非扫描阶段；`keyboard_mode` 表示键盘模式。导航请求区分 `system_back`、`dialog_system_back`、`top_button` 和业务回调。路由只记录类型，不记录单据、SKU 或业务 ID。

## 验证

自动测试覆盖 API 28 与 API 36 的有效/无效广播、600 毫秒边界、重复扫描、后台与模式切换、按键配对、编辑输入保护、子页面返回、弹窗返回/触摸取消、事件记录上限和隐私。

运行 `:app:testDemoDebugUnitTest`、`:app:spotlessKotlinCheck`、`assembleDemoDebug`。自动测试不能证明特定 PDA 固件已修复；真实设备验收需检查实体侧键、连续扫描、扫码后人工返回以及手动数量输入。若问题仍存在，先根据诊断定位事件时序和来源，再增加针对性兼容规则。
